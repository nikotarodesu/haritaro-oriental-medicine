### 候補同士の違いと次の四診確認

- 比較画面の変更履歴に変更前後と連動した所見をまとめ、直前の修正1件を戻せるようにする。取り消しは変更したキーだけに限定し、後から編集した別の所見・候補・治法を保持する。対象の所見が別の画面で変更されていたら取り消しを無効化する。
- 履歴は画面を開いている間の直近20件で、再読み込み・所有者変更・新規記録では引き継がない。下書きには修正後の所見を保存し、履歴から取り消した値も同じ経路で保存・再照合する。保存エラーは取り消し後も隠さない。
- 四診の「問診へ・望診へ・聞診へ・切診へ」を削除。四診グループ、候補別比較、見分け方・追加確認のアコーディオンはすべて初期状態で閉じる。利用者が所見への移動を選んだ場合は対象グループを開いて入力欄へフォーカスする。

- 共通する支持所見も押すと同じ場所に修正欄を開く。共有される入力・更新処理で候補の絞り込みと違いを再計算し、なし・未確認へ変更しても操作中の所見を確認状態付きで保持する。共通支持の件数には、現在「あり」の所見だけを数える。

- 入力済みの違いにある「入力を見直す」は、その所見の直下に修正欄を開く。四診画面へ遷移せず、既存の共通入力・更新・保存処理を使う。未確認へ戻した所見と先頭6件の表示境界をその比較中は保持し、固定刺痛など複合項目も続けて修正できる。

- 追加確認する所見は候補比較内の選択欄から直接入力できる。四診画面と同じ選択肢・旧入力の解釈・更新処理を使い、そのイベントで下書き保存し、候補の支持・不一致・表示フィルターと候補間の違いを再計算する。固定刺痛は痛みの性質と部位変化の両方で確認する。
- 入力後は、その比較中の確認欄と折りたたみ境界を保持する。入力済みとして同じ場所で修正・未確認への戻しができ、苔の整合処理で複数項目が変わっても操作中の欄を消さない。候補・比較対象・治法・安全確認を自動変更しない。

- 選択した候補から2〜4件を並べ、すべてに共通する入力済みの支持所見と、候補によって関連づけが違う入力済み所見を表示する。比較対象の切替は候補の採用・保留や治法の入力を変更しない。
- 追加確認は、既存の支持・不一致の両対応表から、候補間で関連づけが異なる未確認項目を抽出する。舌色など同じ入力欄の所見はまとめ、元の入力欄に戻って確認できる。自由記述や未確認から所見を推測しない。
- 観察状態（あり・確認してなし・未確認）と候補との関連づけ（支持・合いにくい・照合設定なし）を分ける。対応表に記載がないことを否定材料にせず、合いにくい所見がないことを支持と数えない。
- 照合定義が同じ候補ペアは現在の入力項目だけでは見分けられない旨を表示し、各候補の既存の見分け方・追加確認と四診の補足記録へつなぐ。臨床ルールや診断順位・確率は追加しない。
- `clinical-candidate-differential-regression.cjs` と画面・ワークスペースの回帰検証で、支持と不一致、確認してなしと未確認、入力欄の重複排除、旧データ・苔の矛盾、4件の比較上限、元の候補と治法の保持、入力欄への移動を検証する。

### 四診所見から候補を絞る

- 候補選択画面に「支持所見あり」と「複数の四診で支持」の表示フィルターを追加。後者は問診・望診・聞診・切診のうち2つ以上に支持がある候補で、舌の複数項目を複数の四診として数えない。
- 各候補に支持のある四診と具体的な支持所見・合いにくい所見・確認して認めなかった支持所見の件数を表示。絞り込みは既存の照合結果を使い、表示順はカタログ順を保つ。支持件数による診断順位・確率・重みづけは追加しない。
- 合いにくい所見がある候補も絞り込みに残し、混在所見を確認できるようにする。全候補へ戻す操作で所見・検索・分類のフィルターを解除できる。候補のチェック状態、自由入力の治法、配穴を自動変更しない。

### 舌診の詳細と全四診の候補比較への接続

- 舌体は色・大きさ厚み・歯痕・裂紋・瘀点瘀斑・乾湿、舌苔は色・厚さ・性状・乾湿を独立した入力に変更。歯痕と裂紋を同時に記録でき、旧形式の舌の形も保持する。
- 既存19所見の比較に、詳細所見の明示的な照合表を追加。例：淡白舌・胖大・歯痕を脾の不足の候補、紅舌・少苔・舌の乾燥・細い脈を陰虚の候補、厚苔・膩苔・滑脈などを湿の候補の材料として表示。既存の候補ID・配穴例・治法の手入力を維持する。
- 舌色・苔の性状・速さ・強さ、固定して刺す痛みは既存所見との共通の解釈関数を通す。表示、比較、保存に同じ結果を使い、古い有無フラグが新しい詳細入力を上書きしない。刺す痛みと固定部位が両方確認されるまで「固定した刺すような痛み」を支持にしない。
- すべての選択・測定値・補足は比較画面の入力要約に表示。候補別に照合根拠を設定していない所見（経過、局所圧痛、筋緊張、皮膚温、脈拍実測値、左右差、不整など）は追加評価欄に残す。局所皮膚温を全身の寒熱、圧痛を証、脈の不整を特定の臓腑の証へ自動変換しない。
- 空欄・判断困難・混在・自由記述から支持所見を生成しない。「日中の発汗が多い」を自汗と同一視せず、実測脈拍から数脈を決めない。複数条件を持つ所見の二重集計は避ける。
- 「苔を認めない」の入力は苔の4項目を整合させ、再び色などを選ぶと他の「苔なし」を未確認へ戻す。旧下書きで苔なしと厚苔などが混在する場合は警告し、再確認まで苔の比較根拠に使わない。
- 対応表は `src/data/clinicalExaminationComparison.ts`、確認コマンドは `npm run test:clinical`。55の項目・候補構成検証、39の画面入力保存フローなどを実行する。

## 保存と互換性

- 作業中の下書きは `sessionStorage` に保存します。タブを閉じる前に既存の臨床ノートへ保存します。保存が失敗した場合は画面に表示し、転記時は遷移を止めます。
- 保存済みノートは既存の `PatientNoteItem` を使います。所見・採用理由・評価指標は `treatmentPlan` の人が読める項目として保持するため、既存のローカル保存・同期・JSON/CSV出力の形式を変えません。
- 自由記述の既存ノートも表示でき、指標を読めない場合は未記入として扱います。同名指標でも評価条件が違う数値は直接比較しないよう案内します。
- 患者情報や入力本文はURLへ含めません。患者向けセルフケアの経穴欄へ、施術用経穴を自動転記しないよう修正しました。
- 医療評価を優先する状態では配穴を保留し、ノートへの配穴転記も行いません。安全確認の未完了時は配穴の作業を止め、再来時は安全確認を再入力します。

## 確認の限界

所見の照合は本サイトが整理した限定的な伝統医学の学習モデルです。診断精度・治療効果・本モデルの臨床的妥当性・専門家監修は未確認です。WHOの標準用語は用語体系の参照であり、照合ルールや個別配穴の効果の裏付けとは扱いません。81講義への実践案内の追加は、全本文の医学的照合や監修の完了を示しません。

今回は未ログインでの保存と操作を検証しました。新しい実アカウントでのクラウド往復や実患者による使いやすさの評価は実施していません。
