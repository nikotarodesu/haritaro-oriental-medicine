# はり太郎の改善を比較するための計測

実装日: 2026-10-03。医学情報の追加監修はこの改善の対象外です。

## 測るものと定義

| イベント | 発生条件 | 解釈 |
| --- | --- | --- |
| `article_view` / `lecture_view` | 対象ページへ実際に到達 | 読了・学習開始とは区別する |
| `quiz_start` | 講義の理解度チェックで最初の未回答の選択肢を押す | 保存済みの途中回答から再開した場合も今回の開始。全問・不正解の再挑戦で開始を取り直す |
| `quiz_answer` | 未回答の問題を回答 | 問題文・選択肢・選んだ答えは送らない。正否の真偽値だけ |
| `quiz_complete` | 講義チェックの全問が回答済みになる | 合否、正解数、問題数。再挑戦の完了も含む |
| `review_start` / `review_complete` | 復習を開始 / 最後の解説を確認して完了 | 既存イベントを利用 |
| `context_link_click` | 記事・講義・コース間のリンクを押す | `placement` で場所、`course_id` / `lecture_id` で公開教材を区別 |
| `learning_activity` | 問題回答・復習/症例演習開始・コースから講義へ進む操作 | 同一ブラウザのローカル暦日に1回。読むだけの利用者を含む全学習者数ではない |
| `learning_return_7d` | 前回の操作日から1〜7暦日後に再び活動 | 同一ブラウザで1日1回。厳密な新規コホートの7日継続率ではない |
| `web_vital_<lcp/inp/cls>_<good/needs_improvement/poor>` | Next.js内蔵の公式web-vitalsが測定を確定 | 実環境での表示・応答・ずれの評価。技術指標を公開UIに表示しない |

コースで学習意図を測る `placement` は `course_start` / `course_resume` / `course_step`。一覧を見る操作や関連記事を押すだけでは活動日に数えません。`course_review` / `course_reading` / `lecture_course_return` などの移動は移動イベントとして記録します。

7日以内の再学習では、ブラウザに前回の暦日文字列だけを保存します。新しい追跡用の個人IDは作成しません。端末変更、ストレージ削除、時差・時計の変更、複数タブの同時操作に影響されます。保存を禁止するブラウザでは、同一ページを開いている間だけ重複を避け、端末をまたぐ継続率として扱いません。現状のアカウント同期・学習保存内容は変更しません。

## Web Vitalsの読み方

計測は `next/web-vitals` の `useReportWebVitals` を利用します。ブラウザ内でINPを独自算出せず、DOM・クリック対象・入力内容・metric IDを外部へ送信しません。LCP/INPはミリ秒、CLSは単位なしの `metric_value`。GAの `value` に限ってCLSを1000倍した整数にします。

各イベント名に評価を含めるため、カスタム定義なしでも端末別の良好・要改善・不良の件数を比較できます。これは正確な75パーセンタイルの数値分布ではありません。数値の詳しい分布が必要なら、GA4のカスタム指標に `metric_value`、カスタムディメンションに `metric_name` / `metric_rating` を登録し、BigQueryなどのイベント単位のデータで評価します。平均値だけを合否判断に使いません。

初回の文書ロードを基準にページを帰属させ、SPAのページ移動そのものの速度とは区別します。操作がなければINPは発生しません。ブラウザの対応状況・広告ブロック等により一部の計測は欠けます。イベントの安定したコールバックと内部重複チェックを使い、同じ通知を二重送信しません。

Google公式の基準は、端末別75パーセンタイルで LCP ≤ 2.5秒、INP ≤ 200ミリ秒、CLS ≤ 0.1。まずスマホで不良の割合が高いページを探し、読み込み・操作の原因を調べます。

## プライバシーと設定

- 公開ページの許可リストを使い、query/hashは外部に送りません。
- `/notes`、`/auth`、`/account`、`/api`、不明な経路ではページビューとカスタム計測を停止します。公開ページからこれらへ移動した場合もGAの停止フラグを設定します。
- 外部参照元はドメインまで。同一サイトの非公開参照元は除去します。
- 検索語、自由記述、ノート、診断内容、連絡先、回答文、アカウントIDを除外します。許可した教材ID・導線・集計数値だけを送ります。
- GA4のGoogleシグナルと広告パーソナライズを無効にし、独自の手動ページビューを使います。
- **GA4管理画面の拡張計測はページビューの「ブラウザの履歴イベントに基づくページの変更」、サイト内検索、フォーム操作を無効にしてください。** 拡張計測の自動イベントは外部設定であり、コードの手動イベント許可リストだけでは制御できません。
- `NEXT_PUBLIC_GA_ID` は、はり太郎専用測定IDを設定します。未設定・仮IDではGoogleタグを読み込みません。

## 28日比較レポート

読み取り専用のサービスアカウントに、はり太郎のGA4プロパティ閲覧権限とSearch Console閲覧権限を設定します。秘密JSONをGitに追加しません。`.env.example` にある以下をローカル環境変数として設定します。

- `GA4_PROPERTY_ID`: 数字のプロパティID（公開測定ID `G-...` とは別）
- `GOOGLE_APPLICATION_CREDENTIALS`: サービスアカウントJSONの絶対パス。未指定時は既存の `credentials/ga4-key.json` を使用
- `GSC_SITE_URL`: 省略時は、権限がある `sc-domain:haritaro.jp` またははり太郎のURLプレフィックスを使用

実行例:

```text
node scripts/growth-report.mjs --dry-run
node scripts/growth-report.mjs --output=reports/growth/2026-10-03.json
```

このコマンドはGA4/GSCへ読み取りだけを行い、設定を書き換えません。GA4はホスト名 `haritaro.jp` / `www.haritaro.jp` に限定します。GSCは対象ドメインの権限が見つからなければ停止し、他サイトへ切り替えません。資格情報・プロパティ・権限が不足した結果はstatusに記録し、欠測を0として扱いません。

集計遅延を避けるため3日前までの28日と、その直前の28日を比較します。GA4とGSCではサービスのタイムゾーン・集計仕様が異なるため完全一致は求めません。上位100ページの抽出には偏りがあるため、特定ページの改善前後を厳密に調べる場合はGA4/GSC管理画面で対象URLを指定します。

## 改善ループ

1. 変更日と対象URLを記録し、改善前の28日レポートを保存する。
2. 流入があるのに講義や問題へ進む人が少ないページを5つ選ぶ。
3. 要点・図解・次に読む導線を直し、スマホでタスクを試す。
4. 新イベントが集まり始めたことをGA4のリアルタイム画面で確認する。
5. 同じ条件・同じ長さの期間を比較する。流入増減、曜日、国試時期などの影響を記録する。
6. 問題完了・復習・再学習の件数と、端末別の表示品質を評価し、次の5ページを選ぶ。

単独の開始/完了件数の割り算は、同じ人の同じ試行の完了率を証明しません。GA4の探索で `quiz_start → quiz_complete` などを同一セッションの順序付きファネルとして確認します。講義別・コース別の内訳が必要なら、`lecture_id` / `course_id` / `placement` をイベントスコープのカスタムディメンションに登録します。再挑戦・保存済みの途中回答からの再開も定義に含め、比較期間をまたぐ学習を考慮します。

新規イベントは実装前には存在しません。実装前の値が空でも学習者がいなかったとは判断せず、実装後に十分な計測期間を確保して基準を作ります。滞在時間だけを成果にせず、「問題を終えた」「次の教材へ進んだ」「別の日に復習した」を合わせて評価します。

## 実利用者に確かめるタスク

次の確認は3〜5人の学生・利用者に、説明を先回りせずスマホで試してもらいます。

1. 経穴名または英数字のコードから目的の経穴を探す。
2. 目的に合う学習コースを選び、講義を読んで理解度チェックを終える。
3. 間違えた問題から解説へ戻り、苦手分野の復習を始める。

完了できたか、迷った位置、押し間違い、所要時間を記録し、計測データと合わせて次の修正を選びます。コード・ブラウザによる検証と、人に試してもらう検証は区別します。**この実装では、実利用者3〜5人による試験は未実施です。**
