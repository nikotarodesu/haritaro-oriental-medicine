# 養生シート用ツボのクラウド同期修正（2026-10-27）

## 接続と原因

ユーザーの再接続後、Supabaseの本番プロジェクト `haritaro-web`（`aeglehibpdsirsrjrjmg`）にアクセスできることを確認した。

アプリは患者向け養生シートに使うツボを `selfCarePoints` に保持する一方、クラウド向けの変換・復元関数と、`public.patient_notes` テーブルには対応する項目がなかった。このためクラウドから読み戻すと、養生シート用ツボだけが抜ける。

## 修正内容

- DBに `self_care_points text[]` を追加した。適用済み移行版は `20261027021246`、名称は `preserve_patient_note_self_care_points`。
- 送受信の変換に `selfCarePoints` と `self_care_points` の対応を追加した。施術用の `selectedPoints` とは分けて保存する。
- NULLは旧形式・未確認、空配列は利用者による明示的な解除として区別する。旧形式や一括保存がNULLを送るときは、既存のツボ一覧を更新トリガーで保持する。空配列を送ったときは解除する。
- トリガー関数は `SECURITY INVOKER`、空の `search_path` を指定し、公開RPCとしての呼び出し権限を与えない。既存の4つの所有者ポリシーとRLSは維持する。
- 初回構築用SQLと移行SQLを揃え、Supabaseの実際の移行履歴とローカルのファイル名を一致させた。

## 検証

- `npm run build`: 型チェックと574ページの生成に成功。
- `npm run test:sync`、`npm run test:clinical`: 成功。
- 追加テストは実際の変換・保存・取得関数を隔離したPostgreSQLに接続し、単体保存、一括保存、ダウンロード、旧形式の省略/NULL、明示的な解除、読込/保存失敗、他アカウントの参照/更新拒否、匿名アクセス拒否を確認した。
- 本番DBへの確認クエリで、列の型が `text[]` であること、架空のツボ配列がレコード型へ変換できること、トリガーの存在、RLS有効、所有者ポリシー4件、権限昇格なし、関数への匿名/認証済みユーザーの直接実行権限なしを確認した。
- 本番の患者記録を読んだり、架空の患者記録を本番へ挿入したりしていない。本番の実アカウントでログインして複数端末を操作する確認は未実施。

端末やバックアップに残っている養生シート用ツボは、修正後の画面で同期すると保存対象に含まれる。過去に保存されていなかった値をDBから推定して復元する処理は行わない。

既存のセキュリティ診断には、パスワード漏洩チェック未有効の警告が1件ある。今回の変更による追加警告はない。認証設定は変更していない。[Supabaseの説明](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)
