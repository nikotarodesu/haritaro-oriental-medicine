# 学習履歴の同期を有効にする

サイト本番のSupabaseは `aeglehibpdsirsrjrjmg` です。現在接続されている `nlrgigjxgikwmvqrwbsk` は別プロジェクトです。別プロジェクトには設定を追加していません。

1. [本番プロジェクトのSQL Editor](https://supabase.com/dashboard/project/aeglehibpdsirsrjrjmg/sql/new)を開きます。
2. `supabase/learning-sync.sql` の全文を実行します。学習履歴テーブルと本人限定のアクセス権限、競合更新を処理する関数を追加します。既存の会員・決済・ノートテーブルは変更しません。
3. スマホとPCで同じGoogleアカウントにログインし、学習画面で「学習履歴をクラウドへ反映済み」と表示されることを確認します。
4. 片方で講義を完了・クイズに回答し、他方で「学習履歴を再同期」を押します。講義の完了、復習予定、回答履歴が一致することを確認します。
5. 通信がない状態で学習し、通信を戻して両端末を再同期します。別の問題の回答が両方残り、同じ問題への複数回答も回答履歴に残ることを確認します。
6. ログアウトして別アカウントに切り替え、前のアカウントの履歴が表示されないことを確認します。

ログイン前の履歴は自動的に会員へ移しません。「この端末のログイン前の履歴を引き継ぐ」から、本人の履歴であると確認して取り込めます。旧形式のブラウザ保存ファイルは移行時に削除しません。

対象は講義の完了・閲覧位置、クイズ回答・復習予定、経穴の学習記録・日次活動、症例演習の判断・理由・結果です。経穴演習の途中セッションはアカウント別にその端末へ保存し、途中の画面そのものは同期しません。臨床ノートや患者の情報を、この学習履歴へ移しません。

設定が未実行の場合や同期に失敗した場合は、その状態を画面へ明示します。「同期済み」は本人確認、読み込み、競合統合、書き込みが通った場合のみ表示します。取得上限やブラウザ容量に達した場合も同期成功と表示しません。

実装検証：`npm run test:sync` はローカルのPostgreSQLで、他人の履歴の読み書き拒否、所有者の変更拒否、匿名アクセス拒否、古い更新の拒否、不正バッチの全件取り消し、同時回答の統合、リセット、採点を確認します。このテストは本番への設定完了や実端末での同期を保証するものではありません。
