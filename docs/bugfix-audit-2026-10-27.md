# haritaro.jp 不具合調査・修正記録（2026-10-27）

調査元: `nikotarodesu/haritaro-oriental-medicine`、開始時コミット `e3c1bc61510199a6f713ac1998d237caf3b689e8`。公開サイトのソースと、本番Vercelのコミットが一致することを確認した。

## 修正内容

| 優先度 | 問題と再現条件 | 対応 |
|---|---|---|
| P1 | 配穴保存がReactの更新関数の実行タイミングに依存し、成功がfalseになったりクラウド書き込みが抜けたりする。修正前の実Providerを、更新関数をキューに入れるテストで失敗させて確認。 | 端末への書き込み完了後に成功を返す。クラウド書き込みをReact更新関数から外し、連続操作でも最新の配穴一覧を使用する。 |
| P1 | 自作配穴の保存が失敗してもフォームを閉じて入力を消す。 | 成功時だけ閉じる。失敗時は入力とフォームを残し、理由を確認して再試行できるエラーを表示する。 |
| P1 | バックアップは配列の有無だけを確認し、不正な記録や `{}` も受理する。既存の一覧を丸ごと置き換える。 | アプリ名・版・全記録の型・重複IDを検査。現在の記録を残して追加し、同じIDは現在の内容を優先する。両コレクションの書き込みが成功した後だけ画面を更新し、2件目の書き込み失敗時は1件目を戻す。 |
| P2 | 教材プリセットの追加は保存上限を確認しない。 | 残り枠だけ追加し、実際の追加件数を表示する。バックアップ追加も上限超過時には取り込まない。 |
| P2 | 404画面の「サイト内を検索」は存在しない `/search` へリンクし、再び404になる。 | 共通の検索ダイアログを直接開くボタンに変更する。 |

読み込み中にアカウントが切り替わったバックアップは中止する。ファイルの読込エラーを表示する。自作配穴ダイアログには入力ラベル、閉じる操作の名前、フォーカス制御を付け、アカウント切替時は前の入力を消す。

バックアップの仕様変更: 現在の記録を一括置換する方式から、未登録IDだけを追加する方式へ変更した。確認文にも表示し、同じIDの現在の編集を古いバックアップで上書きしない。
